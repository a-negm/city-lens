# Product Principles

## 1. Map first
The map is the primary interface. Supporting UI should help users read and interpret the map, not compete with it.

## 2. One clear task at a time
The product should not overload users with too many simultaneous layers or too much simultaneous meaning.

## 3. One active layer at a time
Only one main map layer should be emphasized at once to preserve clarity.

## 4. Clarity over completeness
Do not add data just because it exists. Add data only when it improves understanding.

## 5. Strong signals first
Prioritize data that has stronger evidence, clearer interpretation, and better geographic relevance.

## 6. Explain, do not overclaim
The product should help interpret patterns without claiming causation where causation is not justified.

## 7. AI is secondary
AI may explain or summarize, but it must not control the core model or scoring logic.

## 8. Deterministic core
Scores, comparisons, rankings, and factor contributions must be computed in code, not generated by AI.

## 9. Honest uncertainty
Every meaningful insight should clearly communicate certainty, limitations, or evidence strength where relevant.

## 10. Avoid medical framing beyond evidence
The product must not diagnose, predict individual disease, or suggest clinical conclusions.

## 11. Lightweight interaction
The interface should remain calm, legible, and spatially focused.

## 12. Progressive complexity
Start with a small set of useful features. Add more complexity only after the basics are solid.
